# 关于保存引用编辑

保存引用编辑是引用工作流的不同部分，可用于将您对被引用文件所做的引用编辑“烘焙”回原始被引用文件。将引用编辑保存回被引用文件后，它们将永久成为该被应用文件的一部分。此时，原始文件已永久更改，因此不再将所做的编辑称为引用编辑。

保存引用编辑时，请考虑以下问题：

- 引用编辑无法保存到已锁定的引用。必须先解除文件引用的锁定，然后才能保存编辑。请参见[锁定文件引用](../使用文件引用/锁定文件引用.md)。

- “保存引用编辑”(Save Reference Edits)命令不能撤销。

- 在“保存引用编辑”(Save Reference Edits)操作过程中，会将自动为场景（例如默认摄影机和默认着色器）创建的节点写入到子文件。

## 保存到引用文件的内容

在“保存引用编辑”(Save Reference Edits)操作过程中，会保存在父场景中应用的编辑（具体地说，是 setAttr、deleteAttr 和 addAttr）以及在同一被引用文件中创建和移除连接的命令（具体地说，是 connectAttr 和 disconnectAttr）。会将父场景中仅影响被引用文件中节点的那些节点和连接保存到引用文件。例如，会将仅影响引用文件的构建历史和纹理保存到引用文件中。永远不会将 DAG 节点（例如，主场景中的形状）保存到引用文件，但是以引用文件中的变换为父对象的新构建历史形状除外。

如果您要求在保存引用编辑操作过程中写出新的 DAG 节点，则可以导入被引用文件，以使所有项目都位于场景中，然后仅选择那些导入的项目以及所有新节点，并重新作为引用导出当前选择。这样，对节点和属性所做的所有编辑均将写入导出的文件引用。请参见[导出文件引用](../使用文件引用/导出文件引用.md)。

导入然后导出引用有可能会为随后引用导出的引用的其他场景带来名称空间冲突。建议在导出引用之前移除所有最近从其旧名称空间导入的节点。有关详细信息，请参见[移除名称空间](../../../../名称空间/名称空间/移除名称空间.md)。
